# UooDoo Project Explanation

This document explains what was built, what tools were used, and how the project works in detail.

## What was done

I created a working UooDoo project inspired by the proposal in the PDF. The project was turned into a real software structure with:

- a core C++ library manager
- a console-based app
- a Python GUI version
- a native Qt desktop application
- a test suite for the core logic

The goal was to convert the proposal idea into something practical and runnable.

## What was used

### 1. C++
C++ was used because the proposal described the project as a C++ video loading and playback system.

It was used for the core logic of the project in:

- src/LibraryManager.h
- src/LibraryManager.cpp
- src/main.cpp

This part handles:
- storing information about videos
- adding and removing videos
- marking videos as favorites
- saving the video list to disk
- loading the saved list when the program starts again

### 2. Qt
Qt was used to build a more modern and polished desktop interface.

The graphical desktop application is implemented in:

- uoodoo_qt.cpp

Qt was used to create:
- a dark-themed window
- a library area showing videos
- buttons for adding, removing, and favoriting videos
- playback controls
- a search box

### 3. Python and Tkinter
A simpler graphical version was also created using Python in:

- uoodoo_gui.py

This version provides a lightweight UI and helps demonstrate the idea without needing a full native desktop build.

### 4. CMake
CMake was used to organize the build process in:

- CMakeLists.txt

It helps compile the console app, the Qt app, and the test program in a structured way.

### 5. Tests
A basic automated test was added in:

- tests/library_manager_test.cpp

This test checks whether the core library manager behaves correctly.

## How the project works

### 1. Core idea
The project is based on a video library system.

Each video entry contains:
- the video name
- the file path
- a favorite flag

The system remembers these videos and shows them in a list.

### 2. Adding a video
When the user selects a video file:
1. the program checks whether the file exists
2. it checks whether the file type is supported
3. it creates a new video entry
4. it adds the entry to the library
5. it saves the update so the change is not lost

### 3. Removing a video
When a video is removed:
1. the program finds the matching entry
2. it deletes it from the list
3. it updates the saved data file

### 4. Favoriting a video
When a user marks a video as favorite:
1. the program finds the chosen video
2. it flips the favorite flag
3. it saves the new state

### 5. Saving and loading data
The library manager uses local file storage to save the video list.

This means:
- the app can remember videos between runs
- the user does not need to re-add everything every time
- the data remains simple and easy to understand

### 6. GUI interaction
In the graphical versions:
- the user sees a list of videos
- they can search for a specific video
- they can add new videos
- they can remove videos
- they can mark some as favorites
- they can click playback buttons to open the selected video

The interface is separated from the logic so the system stays modular.

## How the code is organized

### Root folder
The root contains the main project files and documentation.

### src folder
This folder contains the core implementation for the library manager.

### tests folder
This folder contains the test file that checks the main behaviors of the library manager.

### build folder
This folder stores compiled build output generated by CMake.

## Why this structure was chosen

The project was designed in a modular way so that:
- the logic is separate from the interface
- future improvements can be added easily
- the app can be tested more simply
- the code is easier to understand and maintain

## In simple words

The project started with an idea from the PDF and was turned into a working system that can:
- manage a local video library
- present the videos in a user-friendly interface
- save data locally
- support basic favorites and removal actions
- be built and tested in a structured way

This makes it a good starting point for a real media application.
